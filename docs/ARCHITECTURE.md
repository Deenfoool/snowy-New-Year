# Устройство снежного оверлея

## Жизненный цикл окна

Каждое обычное окно накапливает снег независимо. Шапка следует за окном при перемещении, а её профиль адаптируется при изменении ширины. При сворачивании или разворачивании шапка скрывается. При восстановлении высота снега обновляется по прошедшему времени. Перекрытые части шапки отсечены по геометрии окон выше в порядке наложения.

Win32 может повторно выдать числовой дескриптор HWND. Оверлей обрабатывает событие уничтожения окна и периодически сверяет список окон. Новое окно начинает накопление с нуля. Слепленные шары принадлежат рабочему столу и остаются после закрытия окна, с которого был собран снег.

## Накопление и отрисовка

Снежинки симулируются для видимых дисплеев. Высота шапки вычисляется по сохранённой высоте, прошедшему времени и текущей скорости накопления или таяния, с учётом ограничения высоты. Отдельный профиль описывает углубления, оставленные шаром. Снегопад постепенно заполняет углубления, даже если шапка уже достигла предельной высоты.

Оверлей использует слоистые окна Win32 и предумноженный альфа-канал. Для неподвижных шапок сохраняются растровые буферы. При паузе и блокировке дисплея отрисовка приостанавливается. Полноэкранный режим учитывается для каждого дисплея отдельно, если эта опция включена. Когда анимация не нужна, оверлей обновляется по событиям и периодической сверке окон.

## Погода

WeatherAPI запрашивается в фоновом потоке. Успешное наблюдение записывается в локальный кэш. При ошибке интерфейс показывает последние сохранённые данные. Погодное наблюдение влияет на накопление в пределах срока актуальности. Ручной режим задаёт снег, ветер и температуру из настроек.
